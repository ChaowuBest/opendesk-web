# 办公室 (Agent Office) GUI 验收测试用例

---

## 前置条件

### P-AGO-01：已存在至少一个可对话的数字员工

1. 打开 OpenDesk 应用启动器，找到并打开「办公室」应用窗口。
2. 切换到「员工管理」标签页。
3. 若列表为空，点击「新建员工」，填写员工姓名、创建者、头衔，点击「保存」。
4. **预期**：员工卡片出现在列表中，状态为「已启用」。

### P-AGO-02：已准备一个数字员工 zip 包

1. 按 P-AGO-01 创建一个员工。
2. 进入该员工详情页，点击「导出 zip」，保存生成 `<姓名>.zip` 文件。
3. **预期**：得到一个可导入的数字员工 zip 包。

## 测试用例

### TC-AGO-001：应用打开与标签页切换

**前置**：已安装「办公室」应用

| 步骤 | 操作                           | 预期结果                                                 |
| ---- | ------------------------------ | -------------------------------------------------------- |
| 1    | 从应用启动器打开「办公室」应用 | 打开应用窗口，顶部显示「办公室」和「员工管理」两个标签页 |
| 2    | 点击「办公室」标签页           | 显示办公室对话界面（员工列表 + 聊天区）                  |
| 3    | 点击「员工管理」标签页         | 显示员工卡片网格和工具栏（导入 zip、新建员工）           |

**判定**：标签页缺失或切换后内容未变化 → 失败

### TC-AGO-003：员工列表选择与搜索

**前置**：P-AGO-01（至少 2 个员工，名称不同）

| 步骤 | 操作                                   | 预期结果                                           |
| ---- | -------------------------------------- | -------------------------------------------------- |
| 1    | 点击「办公室」标签页，观察左侧员工列表 | 每个员工显示头像、姓名、头衔、状态                 |
| 2    | 点击某个员工行                         | 该行高亮，右侧聊天区加载该员工最近消息并滚动到底部 |
| 3    | 在搜索框输入其中一个员工的姓名         | 列表即时过滤，仅显示匹配员工，其他行隐藏           |
| 4    | 清除搜索框                             | 恢复显示全部员工                                   |

**判定**：点击员工无高亮/消息加载，或搜索过滤无效 → 失败

### TC-AGO-004：发送消息（正常）

**前置**：P-AGO-01

| 步骤 | 操作                             | 预期结果                                                                     |
| ---- | -------------------------------- | ---------------------------------------------------------------------------- |
| 1    | 在办公室页选中一个员工           | 聊天区显示输入框，提示「输入消息+Enter 发送+Shift+Enter 换行」及「发送」按钮 |
| 2    | 输入一段消息，点击「发送」       | 消息出现在聊天区；输入框清空                                                 |
| 3    | 在输入框输入另一段消息，按 Enter | 消息发送，出现在聊天区                                                       |
| 4    | 按 Shift+Enter                   | 插入换行而不发送                                                             |

**判定**：消息未发送到聊天区或 Enter/Shift+Enter 行为不符 → 失败；依赖模型响应超时 → BLOCKED

### TC-AGO-005：发送消息（空输入/停用员工）

**前置**：P-AGO-01；另准备一个已停用的员工

| 步骤 | 操作                                                     | 预期结果                                 |
| ---- | -------------------------------------------------------- | ---------------------------------------- |
| 1    | 输入框为空时点击「发送」                                 | 无任何反应，不发送空消息                 |
| 2    | 在「员工管理」中进入某员工详情，关闭「启用这位员工」开关 | 该员工状态变为「已停用」                 |
| 3    | 回到办公室页选中该停用员工                               | 输入框和发送按钮不可点击，无法输入或发送 |
| 4    | 重新启用该员工                                           | 输入框与发送按钮恢复可点击               |

**判定**：空输入被发送、或停用员工仍可输入发送 → 失败

### TC-AGO-007：新建员工（取消/必填校验）

**前置**：无

| 步骤 | 操作                                         | 预期结果                                                         |
| ---- | -------------------------------------------- | ---------------------------------------------------------------- |
| 1    | 点击「新建员工」，不填任何字段，点击「保存」 | 必填字段（员工姓名、创建者、头衔）对应输入框标红并聚焦首个无效项 |

| 4    | 再次点击「新建员工」，点击右上角 ×           | 模态框关闭，无员工创建                                           |

**判定**：必填校验未生效、或取消后产生新员工 → 失败

### TC-AGO-009：员工详情——基本信息自动保存

**前置**：P-AGO-01

| 步骤 | 操作                         | 预期结果                                                               |
| ---- | ---------------------------- | ---------------------------------------------------------------------- |

### TC-AGO-011：MCP 管理——JSON 校验

**前置**：P-AGO-01

| 步骤 | 操作                               | 预期结果                                                                      |
| ---- | ---------------------------------- | ----------------------------------------------------------------------------- |
| 1    | 进入员工详情页，打开「MCP 管理」段 | 显示 mcp.json 编辑文本域                                                      |
| 2    | 输入非法 JSON（如 `{invalid`）     | 文本域标红，显示「MCP 配置不是有效的 JSON」，自动保存指示器显示「请修正内容」 |
| 3    | 输入合法 JSON 但 servers 非数组    | 显示「mcp.json 的 servers 必须是数组」，不保存                                |
| 4    | 输入合法 JSON（servers 为数组）    | 自动保存，指示器显示「已保存」                                                |

**判定**：非法/非数组 JSON 未被拦截或合法 JSON 未保存 → 失败
