# 内置浏览器账号密码

内置浏览器在用户点击登录提交按钮或按回车时识别账号/密码表单，首次提交新账号时弹出“是否保存密码？”确认，仅显示问题和取消/保存按钮，没有正文，用户明确点击保存后才写入。已有账号的密码发生变化时，通过所属浏览器地址栏下方靠右、不抢焦点的固定非模态卡片展示旧密码、新密码，用户确认后更新；密码默认遮罩，可点击显示。提交不等同于服务端登录成功。再次点击账号框（或通过 Tab 进入账号框）时，页面内的非模态候选列表列出当前站点已保存的账号；选择后填入账号和密码，并派发 input/change 事件。

## 支持边界

- 首版支持主框架中账号和密码同时可见的标准表单，包括动态插入的表单和可访问的 Shadow DOM。账号输入使用 text/email/tel，优先识别 autocomplete=username。
- 注册/重置密码的 new-password 字段、多个可见密码框、隐藏/只读字段和一次性验证码不参与填充。
- 分步登录、iframe 内登录、封闭 Shadow DOM、仅通过自定义非提交按钮发起的登录暂不支持。不会自动点击登录或判断服务端登录结果。
- 仅 HTTPS 和 HTTP 本机回环地址启用；账号严格绑定协议、主机和端口，不在子域名之间共享。候选列表不抢焦点，输入、点击其他位置或按 Esc 会关闭；密码框不会触发列表。键盘选中账号需要先按方向键，再按回车。更新提示不随网页跳转关闭，也没有回车默认同意；关闭提示保留旧密码。
- 没有云同步、Chrome 密码导入或逐条密码管理；现有浏览器设置的“清除密码与自动填充数据”和“清除所有浏览数据”会删除全部保存记录。

## 数据与隔离

账号、站点和密码整个文件经 Electron safeStorage 加密，存放在应用 userData/browser-credentials.enc。系统加密不可用或使用 basic_text 后端时拒绝存储，不降级到明文。写入采用临时文件后重命名，损坏或无法解密的文件不会被新记录覆盖。

浏览器 guest 开启 contextIsolation、sandbox，关闭 nodeIntegration。页面无法取得凭据 IPC 接口；预加载脚本仅处理真实输入事件。主进程从 IPC senderFrame 获取当前站点，只接受浏览器分区的主框架。主进程只向隔离预加载脚本提供本站用户名候选，不提供密码。用户明确选择后，通过绑定当前页面和清除版本的一次性令牌获取选中账号的密码。列表置于 closed Shadow DOM，不向网页暴露填充接口。页面脚本可以读取已经填入自己页面的字段，这是自动填充的正常边界。

导航会使旧列表选择失效；清除数据会立即关闭已打开的保存/更新卡片，同时使待确认保存和待选择填充失效。代码不向日志输出账号或密码，也不引入轮询。原有 window.open 和焦点脚本经 contextBridge.executeInMainWorld 同步进入页面上下文；不支持该 API 的旧版 Electron 使用异步注入兼容路径，该路径未做设备验证。

是否重复保存由主进程根据当前密码库判断，页面不缓存上次提交的账号密码。清除后，仍打开的登录表单可再次提交相同内容并重新触发保存确认，无需刷新或重新输入；取消保存或更新后也可再次提交并确认。确认提示尚未结束时，主进程会忽略并发提交以避免重复弹窗。

## 模块职责

密码服务位于 `src/main/services/browser-credentials/`，通过宿主 webview 生命周期接入，不依赖应用浏览器的菜单、面板、历史、收藏、下载或设置 UI。两处浏览器原有的菜单与功能布局保持不变。

应用浏览器仅在已有的“清除密码与自动填充数据”和“清除所有浏览数据”后端操作中调用密码库清除入口，不修改菜单、面板、样式或其他功能。

- `store.ts`：加密持久化、站点隔离、清除通知，不持有进程级实例。
- `runtime.ts`：创建唯一密码库实例；初始化和设置页清除共用此入口。
- `manager.ts`：guest IPC 来源校验、一次性填充令牌、保存确认与清除竞态。
- `save-prompt.ts`：可信宿主提示的调用和取消生命周期；`prompt-view.ts` 是自包含的宿主注入脚本，不在主进程执行 DOM 操作，也不访问密码库或 IPC。
- `browserCredentials.ts`：隔离 preload 内的表单识别与填充交互，不暴露凭据接口给网页。
- `confirm-button-styles.ts`：通用确认按钮样式与主题令牌，无 Electron 或 DOM 依赖。

## 验证

仅保留必要单元测试：持久化/更新/清除、IPC 来源与一次性选择、保存确认及清除竞态、提示 DOM 生命周期。DOM 单元测试不验证浏览器排版或真实鼠标事件；系统钥匙串、真实账号登录、Windows/Linux/鸿蒙设备仍需手工验收。

## 开发版加载

主进程凭据接口与网页预加载脚本需要来自同一次构建。构建后应退出并重新启动开发版；仅刷新或新开网页可能把新预加载脚本连接到仍运行的旧主进程，导致候选请求找不到处理器。

保存/更新卡片挂载在可信宿主页面，根据发起登录的 webContentsId 跨 Shadow DOM 找到所属浏览器工具栏，紧贴其下沿及浏览器面板右边缘，外框为直角，不创建额外 BrowserWindow；颜色使用 --od-_，字体和字号使用 --font-_ / --fs-\*，随全局主题及字体设置实时继承。按钮复用通用确认弹窗的样式及 --mc-\* 红色明暗主题配色。卡片使用 Shadow DOM 隔离组件样式，明确点击按钮才确认，网页导航不关闭卡片；宿主导航、网页销毁或清除密码会取消。卡片通过 ResizeObserver、祖先属性变化与滚动/窗口尺寸事件跟随面板布局，关闭时解除监听，不轮询。最多显示一张卡片，新请求替换旧卡片时旧请求按取消处理。
