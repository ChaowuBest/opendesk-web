# 目标机制实现说明

本文档记录目标机制实现过程中有意延后，或以保守方式实现的事项。

## 由于当前架构而延后的事项

1. 完整上下文投影目前只完成了部分接入。
    - 已实现：消息和工具调用会附带目标/插曲元数据；评估器使用目标投影辅助函数；受目标控制的任务轮次会将投影后的活跃上下文传递给 `prepareContextForModel`、token 估算、工具结果预算分析以及适配器消息构造。
    - 已实现：完整压缩边界和会话记忆压缩边界现在会记录投影来源，以及从限定作用域的压缩输入派生出的 `summarySegments`，因此目标投影可以保留全局/当前目标片段，同时丢弃插曲和其他目标的内容。
    - 已延后：用按作用域独立经 LLM 压缩的摘要替换保守的序列化片段文本。
    - 原因：当前的压缩写入器仍然会为普通转录生成一个主要的合成文本摘要。额外的 `summarySegments` 是投影安全的，但有意保持保守，以避免在没有更完整提示词和预算设计的情况下臆造按作用域生成的 LLM 摘要。

2. 压缩边界来源尚未完全分段。
    - 已实现：压缩边界的投影元数据和摘要片段会被保留；新生成的完整/会话记忆压缩边界会记录保守的来源信息以及生成的片段；目标投影只保留全局/当前目标片段，并丢弃插曲、其他目标以及没有来源信息的旧边界。
    - 已延后：重写已经以单个非结构化文本块形式存储的旧压缩摘要。
    - 原因：现有压缩摘要是以合成转录产物的形式存储的，缺少足够的结构化来源信息，无法在事后安全拆分。

3. GUI 控件保持最小化。
    - 已实现：主进程 IPC、preload API 暴露、工具栏创建目标入口、任务渲染目标摘要、侧边栏徽标、目标面板编辑/暂停/恢复/清除按钮、预算受限的一次性授权和 +1 次尝试授权按钮、渲染进程中的活跃目标停止控件会调用目标暂停而非普通任务停止，并且 GUI IPC 可以向共享恢复服务传递显式预算覆盖值。
    - 已延后：面向任意时间/token/尝试次数数值的更丰富可视化预算编辑器。
    - 原因：共享预算覆盖路径已经实现，但完整的数值预算编辑器需要更多 UI 设计，不适合塞进紧凑的目标面板。

4. 事件日志产物侧重写入。
    - 已实现：内联事件日志尾部记录，以及在超过内联上限后追加写入 JSONL 产物。
    - 已延后：产物修复、在状态/导出中完整回读产物，以及将现有任务迁移为由产物支撑的历史记录。
    - 原因：当前任务渲染/导出路径消费的是内存中的任务状态，并没有标准的产物水合步骤。

## 语义歧义

1. 受阻目标的恢复分类。
    - 已实现：诸如 "continue"、"retry"、"继续" 和 "重试" 这类简短恢复意图会恢复受阻目标。
    - 已延后：将任意用户消息分类为“可解决阻塞项的补充信息”。
    - 歧义：规范要求忽略无关消息，但没有为与阻塞项相关的信息定义确定性的分类器或阈值。

2. 目标完成证据阈值。
    - 已实现：评估器 schema 会记录 `met`、`not_met`、`blocked` 和 `budget_limited`，并附带原因和证据。
    - 歧义：规范没有定义最低置信度、证据格式，也没有定义低置信度的 `met` 是否应当完成目标。

3. 评估器结果之后的预算优先级。
    - 已实现：在调度下一次继续执行之前，会按时间、token、尝试次数的顺序进行预算检查。
    - 歧义：规范列出了多个预算维度，但没有定义在同一个边界上同时超出多个预算时的优先级。

4. 运行中目标的编辑行为。
    - 已实现：编辑活跃目标会递增修订版本、将旧工具调用标记为过期，并在下一次工具阶段之前注入内部提醒。
    - 已延后：仅因为目标被编辑就强制取消已经运行中的外部工具。
    - 歧义：规范要求提供过期工具保护，但没有明确要求在编辑时取消已经启动的工具。

5. 分叉目标行为。
    - 已实现：分叉后的未完成目标会以分叉历史原因为由进入受阻状态。
    - 歧义：规范提到了分叉/回退/重做/导出/渲染处理，但没有定义分叉应当继承一个已暂停且可编辑的目标、克隆为活跃目标，还是阻塞并等待用户确认。
