# 目标机制实现说明

本文档记录目标机制实现过程中有意延后，或以保守方式实现的事项。

## 由于当前架构而延后的事项

1. 独立上下文筛选层已撤回。
    - 当前事实：消息和工具调用仍会附带目标元数据，但 goal turn 不再向 `prepareContextForModel` 传入专用上下文覆盖；评估器直接读取最近 transcript 摘要。
    - 已延后：如果未来需要 goal-only 上下文隔离，需要重新设计接口、压缩边界语义和验收测试。
    - 原因：现有 goal 控制面优先复用 task runner 的完整上下文，避免错误过滤导致执行信息缺失。

2. 压缩边界来源不做 goal 专用分段。
    - 当前事实：完整压缩和 session memory 压缩只保留通用 boundary metadata，不记录 goal 专用来源片段。
    - 已延后：重写已经以单个非结构化文本块形式存储的旧压缩摘要。
    - 原因：现有压缩摘要是以合成转录产物的形式存储的，缺少足够的结构化来源信息，无法在事后安全拆分。

3. GUI 控件保持最小化。
    - 已实现：主进程 IPC、preload API 暴露、工具栏创建目标入口、任务渲染目标摘要、侧边栏徽标、目标面板编辑/暂停/恢复/清除按钮、渲染进程中的活跃目标停止控件会调用目标暂停而非普通任务停止。
    - 已实现：renderer 订阅取消只移除当前 listener，避免一个组件卸载破坏其他实时刷新订阅；task view 卸载/清理时会清空 artifacts 中的 TodoWrite 状态，避免右侧栏残留上一任务的 running 待办。
    - 已实现：右侧栏用户可见 tab 文案为“任务进展”；TodoWrite 在上、Goal 跟进层在下；goal section 的 timeline 在运行期 `getGoalStatus()` 刷新时仍保留，并优先展示目标创建/编辑等 `objectiveEvents`；GUI 创建 goal 时，如果 task 仍未命名，会用 goal objective 派生左侧栏任务名。
    - 已调整：GUI 创建和编辑入口只处理 objective。
    - 原因：当前 goal 控制面只保留目标推进、暂停/恢复/清除和完成评估，资源限制配置不再作为用户功能暴露。

4. 事件日志产物侧重写入。
    - 已实现：内联事件日志尾部记录，以及在超过内联上限后追加写入 JSONL 产物。
    - 已延后：产物修复、在状态/导出中完整回读产物，以及将现有任务迁移为由产物支撑的历史记录。
    - 原因：当前任务渲染/导出路径消费的是内存中的任务状态，并没有标准的产物水合步骤。

## 语义歧义

1. 暂停/受阻目标的普通消息恢复分类。
    - 已实现：诸如 "resume"、"continue"、"retry"、"继续"、"恢复" 和 "重试" 这类简短恢复意图会恢复 paused 或 blocked goal，并通过 scheduler 消费 pending continuation 或生成默认 resume prompt。
    - 已实现：paused goal 收到非恢复短语时仍允许普通对话，不进入 goal evaluator，也不自动续跑。
    - 已实现：blocked goal 收到无关普通消息时保持 blocked，并返回本地化提示。
    - 已延后：将任意用户消息分类为“可解决阻塞项的补充信息”。
    - 歧义：规范要求忽略 blocked 状态下的无关消息，但没有为与阻塞项相关的信息定义确定性的分类器或阈值。

2. 目标完成证据阈值。
    - 已实现：评估器 schema 会记录 `met`、`not_met` 和 `blocked`，并附带原因和证据。
    - 歧义：规范没有定义最低置信度、证据格式，也没有定义低置信度的 `met` 是否应当完成目标。

3. 运行中目标的编辑行为。
    - 已实现：GUI/API 共享 edit 入口编辑活跃目标会递增修订版本、将旧工具调用标记为过期，并在下一次工具阶段之前注入内部提醒。
    - 已实现：CLI/TUI 已删除 `/goal edit` 指令；CLI/TUI 修改目标应通过新建 goal 并确认替换，或先 clear 后重新创建。
    - 已延后：仅因为目标被编辑就强制取消已经运行中的外部工具。
    - 歧义：规范要求提供过期工具保护，但没有明确要求在编辑时取消已经启动的工具。

4. 完成态 token 展示。
    - 已实现：evaluator 返回 met 后，goal 进入 complete，并继续保留本 goal 已消耗 token；新 goal 创建时会用当时 task 已累计 token 作为新的 `tokenUsageBaseline`，因此下一 goal 从 0 开始计量。
    - 边界：该计量只影响 goal 控制面展示，不删除 transcript，也不清空 task 级累计 token 或 status bar 历史。

5. 分叉目标行为。
    - 已实现：分叉后的未完成目标会以分叉历史原因为由进入受阻状态。
    - 歧义：规范提到了分叉/回退/重做/导出/渲染处理，但没有定义分叉应当继承一个已暂停且可编辑的目标、克隆为活跃目标，还是阻塞并等待用户确认。
