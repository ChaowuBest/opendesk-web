# 未知上下文窗口的运行时预算

当模型配置、内置模型信息和 API 都不能提供上下文窗口时，窗口保持为未知值 `0`。普通请求不携带 `contextBudget`，不按窗口比例主动压缩；超长工具结果的落盘与请求投影仍正常执行。

成功完成的普通请求会记录该次真实 usage。记录按提供商协议、提供商名称、API 地址、实际模型名和凭据摘要隔离，不使用任务累计 token，也不使用失败请求的部分 usage。只有输出用量、没有输入或总用量的响应不能作为容量依据。

收到明确的服务端上下文超限错误后：

1. 优先提取错误中明确标注的最大上下文窗口；不会将被拒绝请求的 token 数当作容量。
2. 错误未给出窗口时，采用该部署上一次成功请求的真实上下文用量作为保守安全预算。
3. 启用现有比例预算：80% 自动压缩线、15% 摘要输出（最多 16384）、5% 余量（最多 10000）。摘要输出还受用户配置的最大输出限制。
4. 使用现有完整轮次边界和逐步缩小摘要输入的恢复机制，保留近期请求及已完成的工具结果，再重试业务请求。若输入本已低于新预算的 80%，先让适配器根据剩余窗口缩小输出预留，避免短上下文无谓压缩。
5. 没有成功用量且错误也未报告窗口时，暂停并提示设置上下文长度。网络超时、限流和空回复均不会触发容量学习。

学习结果只保存在当前进程中，不写回模型配置；重启后重新学习。后续成功请求不会自动改变已经学习的窗口，重复超限只允许预算收紧。用户明确配置的上下文长度始终优先。

用户手动压缩时，可使用已有成功请求用量计算本次摘要预算，且不会因此提前启用自动压缩线。

运行日志中的 `context_budget_learned` 事件记录新旧预算，不包含 API 凭据。新增用户提示分别位于 `src/locale/zh-cn.ts` 和 `src/locale/en-us.ts`。
