# 通用文件监听服务

`src/main/services/file-watch/` 提供按固定路径监听普通文件的基础能力，尚未接入任何业务。
只依赖 Node `fs.watch`、`lstat` 和路径处理，不依赖 Electron、文件管理器、搜索索引或原生桥。
macOS、Windows、Linux 和 OpenHarmony 使用同一实现；实际可监听范围由运行进程的文件系统权限决定。

## 接口

```ts
import { FileWatchService } from './src/main/services/file-watch/service.js';

const service = new FileWatchService();
const subscription = await service.watch(
    filePath,
    (event) => {
        // event.path 是注册时解析得到的绝对路径。
        // event.type 为 changed 或 missing，业务自行决定是否读取或刷新。
    },
    { onError: (error) => reportInternalError(error) }
);

subscription.dispose(); // 取消本次注册，可重复调用。
service.dispose(); // 取消该服务的所有注册，之后拒绝新的注册。
```

- 注册时要求目标是已存在的普通文件，不支持以目录或符号链接作为监听目标。
- `watch()` 成功返回时初始状态已记录，初始状态本身不回调；注册失败会拒绝 Promise 并释放资源。
- 每次注册独立拥有一个父目录 watcher，重复注册互不影响。服务按需创建，无全局单例或隐式启动。
- 取消后不会再启动新的变化回调；已进入业务代码的回调允许自行结束。
- 同步、异步变化回调的异常都会进入 `onError`，不会破坏其他注册。
- 运行期 watcher 或文件状态检查失败时，关闭该注册并调用 `onError`，不把权限错误解释为文件消失。
  未提供 `onError` 时输出内部诊断。错误处理函数自身抛错也会被隔离。
- 错误文本是基础设施诊断；未来 UI 接入方负责映射为本地化提示。`changed / missing` 是协议字段。

## 变化语义

| 情况                                                         | 回调      |
| ------------------------------------------------------------ | --------- |
| 原路径文件的可观察元数据变化，包括修改或被另一个普通文件替换 | `changed` |
| 原路径不存在，包括删除、重命名和移走                         | `missing` |
| 消失后在原路径重新创建文件，且父目录仍有效                   | `changed` |
| 同目录其他文件变化，目标状态未变                             | 不回调    |

服务监听父目录，收到系统信号后只检查目标的文件标识、大小、时间和属性，不读取文件内容。
父目录监听可以在编辑器原子替换文件后继续观察原路径，避免绑定旧文件对象。
对目录信号统一核实元数据，不依赖平台提供的事件名称、文件名大小写或是否提供文件名。
同一轮事件突发会合并，检查过程中到达的新信号会继续核实；不保证一次系统操作对应一次回调。

## 边界

- 不区分本应用和其他程序的写入，不追踪重命名或移动后的新路径。
- 不递归扫描，不轮询，不自动重试或重新注册失效 watcher。
- 只报告观察到的状态变化，不是逐次操作的审计日志。瞬间消失又恢复、或保持全部元数据不变的改写可能无法识别。
- 父目录被移动、删除或替换后的自动恢复不在第一版范围内；调用方按生命周期取消或重新注册。
- 系统文件通知在不同文件系统上存在限制；注册成功不代表网络盘、休眠恢复或漏事件恢复已有保证。

## 验证

- Jest 真实文件测试覆盖修改、重命名、移动、删除、替换后继续修改、删除后重建、取消及回调隔离。
- Jest 生命周期测试覆盖事件合并、检查期间取消、运行期权限/监听错误以及初始化失败释放资源。
- 2026-10-23 将本服务原样打包，通过临时插件在 HM PC 的 OpenDesk 主进程（Node 20.18.1）执行，
  对 `/storage/Users/currentUser/Desktop` 中的文件注册监听，由外部 HDC shell 执行文件操作。
  修改、重命名、移动、删除、替换后继续修改、删除后重建、取消订阅和释放服务均符合上述契约；临时插件已卸载。
  重建时可观察到多次 `changed`，不保证每次操作只回调一次。HDC shell 的物理路径和权限不能代替应用运行环境。
- Windows/Linux 尚未实机验证；实现使用同一组 Node API，不含平台分支。
