================ 重大设计变更（2026-09-18）：身份命名空间 ================
[F→设计] 应需求变更：**虚拟路径与真实路径相同，不再做任何映射**，沙箱只做
    权限控制。已移除：[[roots]] 映射（策略文件出现即拒绝启动）、vpath↔rpath
    翻译、readlink/realpath/symlink-target 的路径翻译、getcwd 虚拟化、
    launcher 命令翻译、--map（接受为 no-op）、--automount（no-op，恒等视图
    即默认）、--src 的映射语义（现在仅等价 --cwd 切换工作目录）、
    跨根 rename EXDEV 策略。全部测试改为真实路径断言。
    保留：全部权限门控、符号链接解析归因、系统允许清单、ask/grants/缓存、
    进程治理、网络管控、防篡改注入。
    语义变化：身份命名空间下不存在"翻译泄露"问题（readlink/realpath 返回
    真实路径即正确行为）；安全推理更简单（策略=真实路径 ACL）。

[F] shebang 解释器绕过：内核加载 #! 解释器不经本层，allowed 脚本可指向
    execute 被拒的解释器。已修复：exec 时 raw-read 首行解析 #!（含相对
    解释器按脚本目录解析），对解释器递归做 EXEC+setuid 判定（深度上限 5）。
    回归：tools/bin/evil.sh（解释器在 blocked 区）拒绝执行；ok.sh 不受影响
[F] 测试基建缺陷（记录以免重犯）：
    - 探针用 syscall(SYS_renameat2) 裸系统调用 → 绕过被测层（这本身就是
      README 声明的边界）→ 测试必须走 glibc renameat2()

    - 静态链接/内联 syscall/openat2 裸系统调用完全绕过（LD_PRELOAD 机制边界）；
      套件含"边界验证"测试实测该绕过真实存在，若未来失效需更新文档
    - 已打开 fd 的读写不受后续策略影响（与 Windows"已打开句柄"语义一致）
    - SCM_RIGHTS 传入的外部 fd 可绕过（需要沙箱外协作者）
    - 共享内存 ask 状态对树内进程可写：恶意进程可直接伪造 allow 条目
      （与"非对抗性"定位一致；如需对抗性，未来改为 launcher 内 broker 进程）
    - 信号/ptrace/netlink/coredump 不管控；mprotect 匿名页转可执行不拦截（JIT）
    - 判定与真实调用之间的 TOCTOU；多线程 chdir 与相对路径竞态（POSIX 固有）
    - glibc 内部少量不经 PLT 的打开（NSS 模块、locale）不在管控内
    - 关闭看护 fd 的子树失去 watchdog 级联（launcher 组清理仍覆盖直接组）
    - shebang 解析读脚本首行发生在 EXEC 规则放行之后，若脚本内容在放行后被
      并发替换存在 TOCTOU 窗口（与内核读取解释器的窗口一致）
    - execveat(dirfd, 相对路径) 执行脚本时，解释器需按 /dev/fd/<dirfd>/name
      重开脚本，/proc 默认拒绝导致失败；二进制执行不受影响
